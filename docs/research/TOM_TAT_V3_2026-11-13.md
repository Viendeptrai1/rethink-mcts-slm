# Tóm tắt công việc 11–13/11/2026: protocol v3 và đợt benchmark nhiều model 7–9B

Mọi con số dưới đây lấy từ artifact trong repo. Số liệu chi tiết ở [BENCHMARK_LEDGER.md](../results/BENCHMARK_LEDGER.md); các quyết định ở [DECISION_LOG.md](DECISION_LOG.md) (D-006, D-007, D-008).

## 1. Vì sao làm lại

Review code bản 14B (protocol v1) cho thấy hai cơ chế cốt lõi của RethinkMCTS chưa chạy đúng:

- Block analysis bị bỏ: 0/1.203 lần đi vào feedback.
- Rethink không thấy thought cần sửa.
- Critic không có tác dụng vì search dừng sớm.
- Ngân sách tính cả lần rethink, nên cây chỉ sâu tối đa 2.
- MCTS chưa được so với baseline cùng chi phí.

Vì vậy kết quả v1 chỉ đưa vào phụ lục. Đề tài giữ nguyên tên, nhưng vấn đề được xác định lại là **tái hiện và kiểm chứng RethinkMCTS trên nhiều model mở 7–9B, so với baseline cùng ngân sách** (D-006). Khung báo cáo mới: [KHUNG_BAO_CAO_v2.md](../report/KHUNG_BAO_CAO_v2.md).

## 2. Protocol v3 và v3.1

| Thành phần | Thiết lập |
|---|---|
| Search | 16 rollout (lần rethink không tính vào), width 3, 1 rethink/node, P-UCB c=4, Max backup, không dừng sớm (tính lại offline) |
| Reward | 0,8 × public pass + 0,2 × critic ∈ [-1, 1]; critic chỉ gọi khi pass hết public |
| Prompt | Bộ mới `prompts/native_v3/`: rethink thấy thought cần sửa, analysis có test lỗi, critic thấy các thought |
| Sinh code | Temperature 0; giới hạn output v3.1: expansion 1.024, code 4.096, rethink 512, analysis 3.072, critic 256 token (D-007) |
| Baseline | Direct (temperature 0) và Best-of-16 (temperature 0,8, top_p 0,95, chọn theo public pass rate) |
| Dữ liệu | APPS-300 (cohort cố định, public = một nửa số test khác nhau) và HumanEval-164 |
| Model | Qwen2.5-Coder-7B, Seed-Coder-8B, Qwen3.5-9B (tắt thinking); bf16 trên vLLM 0.31.0 |

Code đóng băng ở commit `d9666c4`. Các sửa chính trong `src/rethink_mcts`: đếm rollout riêng khỏi rethink, sửa parser block analysis, truyền thought và test lỗi vào prompt, chạy test song song (16 bài cùng lúc, `test_workers=4`, `max_test_processes=8`), chạy nhiều bài song song trong `run_benchmark`. Có thêm 18 test; cả bộ 85 test đều pass.

## 3. Pilot (20 bài APPS ngoài cohort)

Pilot xác nhận các cơ chế đã chạy thật: 100% analysis vào feedback, cây sâu 3–5. Chạy test song song nhanh hơn khoảng 1,7 lần mà verdict không đổi. vLLM ở temperature 0 vẫn không tất định: 2/18 verdict đổi giữa hai lần chạy. Điều này được ghi vào threats to validity. Gate của Qwen3.5 ở v3.0 fail vì 5,9% output bị cắt, nên nâng giới hạn output thành v3.1 cho mọi model.

## 6. Kết quả sơ bộ (2 model)

Nguồn: [analysis_qwen25c7b_seedcoder8b.json](../results/v3/analysis_qwen25c7b_seedcoder8b.json), tạo bằng [analyze_v3.py](../../scripts/analyze_v3.py).

| Model / Dataset | Direct | Best-of-16 | RethinkMCTS | MCTS so với Best-of-16 (thắng/thua, p Holm) |
|---|---|---|---|---|
| Qwen2.5 / APPS-300 | 17,3% | 28,3% | 28,7% | 22/21, p = 1 |
| Qwen2.5 / HumanEval | 77,4% | 89,0% | 90,9% | 7/4, p = 1 |
| Seed-Coder / APPS-300 | 17,0% | 35,0% | 30,7% | 20/33, p = 0,39 |
| Seed-Coder / HumanEval | 78,7% | 89,6% | 90,2% | 8/7, p = 1 |

Quan sát (chưa phải kết luận, còn chờ model thứ ba):

1. MCTS và Best-of-16 đều hơn Direct rõ rệt ở mọi ô (p Holm < 0,002).
2. MCTS không hơn Best-of-16 ở ô nào. Trên APPS, MCTS tốn khoảng 12 lần token mỗi bài giải được (khoảng 600 nghìn so với khoảng 50 nghìn) và sinh code khoảng 29 lần, so với 16 lần của Best-of-16.
3. Best-of-k: với Seed-Coder trên APPS, Best-of-k bằng MCTS ngay từ k = 6.
4. Bên trong MCTS: so với code đầu tiên của cây, search giúp rõ trên APPS (thắng 29–30, thua 6, p < 0,001). Critic không giúp nhất quán: cộng cả 4 ô thì thắng 8, thua 8.
5. Best-of-16 lấy mẫu ở temperature 0,8 còn MCTS ở temperature 0; khác biệt này phải nêu khi so sánh.
